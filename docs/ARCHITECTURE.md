# Architecture

TypeScript + Vite, Canvas 2D + DOM panels. No UI framework or per-agent DOM nodes. Original pixel artwork, local persistence, and declarative content definitions.

## Modules

Screenshot Life content: `wildlife-defs.ts` contains generic animal parameters and hand-authored pixel grids; `wildlife.ts` updates local feeding, habitats, hazards, stages, contact reproduction and bounded memory. Four-cell spatial buckets constrain animal contacts. `critters.ts` retains the original spider/springtail behavior and owns the combined bounded pool. New wildlife renders in the same reusable pixel layer as ants, with a five-short packet carrying kind/stage/direction/animation bits. `life-ecology.ts` updates registered living cells once per model second. World mutation helpers maintain their active-location set; snapshots save its iteration order for deterministic continuation. This is separate from the existing rolling plant/decomposition ecology and ant heredity model.

`main.ts` owns interface, camera input, and messages. `render/terrain.ts` caches authored 3×3 pixel textures in typed buffers, skips visually unchanged cells and updates one bounded canvas region per packet. `render/agents.ts` compiles hand-authored sprites into sparse pixel writes on one reusable layer; sprites remain individual, with no simulation aggregation. `renderer.ts` composites cached layers. `sprites.ts` contains original grids. Worker packets are acknowledged so only one render frame can be in flight; stale frame queues cannot grow behind input. Brushes are batched once per display frame, with covered stroke areas deduplicated by brush spacing.

`worker/sim.worker.ts` owns `Sim`, fixed ticks, serialization and IndexedDB. Base rate is 30 ticks/s, independent of requestAnimationFrame. A 12 ms compute budget with timer yields caps accelerated work; excess catch-up debt is dropped and counted rather than changing timestep or freezing input. Warp runs as fast as that budget permits. Render messages are sent at most approximately 30 Hz; the camera renders independently. Statistics are sampled four times/s; costly overlays approximately three times/s. Hidden tabs pause and resume their prior run state.

Run commands carry a monotonic UI revision. The worker acknowledges that revision in immediate and periodic status packets; the UI discards statuses older than its latest request. This prevents an old pause sample from reversing the next Play/Pause click during world creation/loading or rapid toggles. This control revision is session state, separate from deterministic simulation ticks and save data.

`sim/world.ts`: typed material, quantity, moisture, ownership, flags, toxicity and scheduler arrays. Coarse temperature/humidity fields at four-cell spacing. Chunks track dirty rendering and active terrain. `materials.ts` is the physical registry.

Mixtures add a Uint8 water-carrier layer, Uint32 composition/progress layer and Uint32 cosmetic stain layer. These stay separate from quantity and soil moisture. `liquid-reactions.ts` performs cardinal-contact, finite-reagent and phase rules through validated multi-cell transactions and named resource deltas. Counts gate adhesion/fictional exposure checks when relevant material is absent. Sparse stain changes travel independently of terrain chunks, so cosmetic painting does not wake physics. The renderer caches stained tile states and updates a bounded dirty region. The registry currently has 134 paintable materials; material IDs and terrain packets remain Uint8 and must be widened before adding ID 256. Frozen composition already reserves 16 bits for origin IDs.

`sim/physics.ts`: falling water and grains over active chunks, rolling moisture exchange, coarse thermal diffusion, humidity and seasonal weather. Bottom/sides are closed for liquids; gases can escape at a boundary. Water is integer units, 64/full cell, separately tracked from absorbed moisture. `sandbox-physics.ts` adds phases, gas movement, density/viscosity, combustion, conduction, corrosion, cooking and devices. Reactive-chunk counts wake material checks when temperature changes. All food/water creation and destruction is ledgered. These are local numerical approximations, not Navier–Stokes, chemistry, oxygen-budget or energy-conserving solvers. See SANDBOX-FEATURES.md for explicit rules and limits.

`sim/ants.ts`: pooled structure-of-arrays storage, spatial buckets four cells wide and fixed-size per-ant memories. `behavior.ts`: decisions every four ticks, movement accumulators every tick, physiology every ten ticks, task FSM, local food sensing, contact interactions and threshold learning. Contact combat searches bounded local buckets and respects intervening cells. Newly buried ants escape locally or die; they cannot move into solid cells.

`sim/signals.ts`: per-colony fields allocate chunks only where used, decay and free empty chunks. Trails are substrate deposits with material-dependent persistence and no diffusion; liquids wash them out. Nest and alarm cues spread through connected gas/plant cells. Walls and liquids block airborne exchange. Fields are bounded by world area and colony slots. The stable chunk iteration is deterministic within one code version, although diffusion across chunks is an ordered numerical approximation.

`sim/colony.ts` and `sim/sim.ts`: aggregate stores, queen reserves, brood, reproduction, ledger, stimuli and lineage. Colony updates every 30 ticks; ecology every 60; nest scans every 300. Brood carries genomes and parent identifiers from conception. Queens never issue per-worker commands. Mature colonies rear alates, which physically leave before mating resolution and daughter landings.

`sim/genetics.ts`: unlinked quantitative allele model; diploid females and haploid males; development fixes adult phenotype. Trait costs act through metabolism, brood feeding cost, movement, attack, clearance, signalling and water loss. Random mutations occur when new gametes are formed, independent of pressure. `species.ts` is a validated declarative content registry. `ecology.ts` and `critters.ts` add plant/food production and decay, prey, predators and contamination. Food production is ledgered, not claimed as conservation of all biomass.

## Explicit navigation and organizational shortcuts

Workers sense local food, signals, contacts, and their route waypoints. A flood-fill over at most a bounded nest region builds a shared distance-to-exit helper. It represents the nest's familiar architecture, **not knowledge of distant resources**. Terrain edits invalidate it. Fallback home steering can use the nest entrance vector (an abstract homing compass). Brood-care candidates are sampled from nearby known nest cells. Congestion and repeated failures bias workers away from failed actions.

Workers can read colony-level hunger/nursing/crowding stimuli and use aggregate stores. This approximates distributed information exchange and trophallaxis. It is not an individual biochemical-contact network. Brood relocation works; whole-colony queen relocation does not.

## Persistence

Schema 3, tagged typed arrays, gzip portable exports and structured clone for IndexedDB. Schema 1 migrates with a zero electrical field; schema 2 gains zero mixture-carrier, composition and stain layers. Validation checks carrier capacities, frozen origins, reaction progress and colors before restoration. Saves include terrain, moisture/thermal/electrical/mixture fields, CA activity schedule, organism arrays and temporary fictional protection, brood, stored sperm, genomes, RNG, signals, stores, pending commands, lineage, mutations, exposure, events and scenario rules. Active living-cell iteration order is retained. Snapshot components are detached exactly once rather than cloning the entire assembled snapshot a second time. UI-only camera/brush/sound preferences and Undo stacks are session settings. Copying/compression happens off the UI thread but is not incrementally streamed; very large exports can delay worker ticks.

Snapshots are detached from live mutable records. Restoring preserves the active CA scheduler and pending surface-column updates; resetting chunks or discarding pending column work used to change continuation and was fixed. Older files missing those scheduler fields still load, but cannot promise identical continuation. Migration accepts schemas 1 and 2 and rejects unknown future versions before constructing a world.

Determinism boundary: the same source revision, settings, initial seed and ordered command schedule in the same JS engine. `replay.ts` reconstructs runs; tests compare core hashes and save continuation. A hash is a regression check, not a cryptographic or comprehensive state identity. Imported custom definitions/settings must be identical. Cross-browser and cross-version replay are not guaranteed. Command logs above 20,000 truncate and mark a run non-replayable; current-world saving still works.

## Performance and bounded history

No all-pairs ant loop or per-ant global path search. Movement uses local candidates; environment and ecology use active chunks/coarse fields/rolling row slices. Temperature and humidity do scan their small coarse grid periodically. Overlay rasterization and conservation audits scan the world at diagnostic frequencies, not per-ant. Render dirty chunks and visible-agent culling reduce work.

Events retain 400; mutation records 3,000; trait history 3,000; exposure 200 days/colony; UI lineage detail 300 records. Full lineage storage remains cumulative to preserve genealogy, so indefinite sessions are **not proven memory-bounded**. Ant array capacity grows to high-water population and reuses dead slots. Signal chunk count can grow to world area for each colony; presets bound colonies, with at most 255 slots. Frame buffers are allocated/transferred per packet and garbage collected; no zero-allocation claim is made. The provided benchmark reports actual memory samples. Consider incremental archiving and double-buffer reuse before claiming large, indefinite workloads.
